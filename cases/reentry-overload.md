# Reentry Overload

## Expected

user 离开数天返回工作区时，先经整体视图看清哪些事项待决定、哪些在推进，再按需展开负责 Mate 的固定状态入口理解现状并作出判断

## Actual

旧面板按十二小时时间窗口过滤，三天后直接显示零行。负责 Mate 缺少固定状态入口，只能抛出决策清单与长篇简报，user 反馈改动过多看不过来、整体与细节都难以掌握，无法理智判断

## Evidence

- 原始案例：建设区事件序号 290，标识 `reentry-overload`，记录于 2026-11-16
- user 原话明确表达拒绝盲目同意，需要按原诉求先看清现状再分组判断

## Inference

短时间窗口隐藏了仍在途的事项，且缺少统一的分层只读视图把待决、留意与进展按原诉求聚合在首屏
