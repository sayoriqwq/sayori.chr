# Lint

## Layers

依据 [VISION 的脚本管机制与 agent 管判断](../VISION.md#tenets)，本仓将质量守卫按性质拆分为两层：

| 层级 | 执行者 | 时机 | 守卫范围 |
| --- | --- | --- | --- |
| 确定性结构校验 | `.ok/scripts/{derive,links,lint}.mjs` | 每次修改与提交前 | 字段完整、自动路由、链接可达、不动点无环 DAG、单向依赖、实现名零泄漏与写作硬格式红线 |
| 定期语义本体巡检 | 独立只读审阅 agent | 理论大幅扩张、新增领域或阶段收口前 | 本体正交性、前提可推性、抽象与实例分层、跨领域逻辑闭合与愿景一致性 |

## Structural

`node .ok/scripts/lint.mjs` 每次扫描全部受管文档并执行以下确定性规则：

- **不动点无环 DAG**：`theory/premise.md`、`theory/language.md` 与 `theory/primitive/` 下页面零向上链接至上层领域、设计层或精选案例
- **理论单向独立**：`theory/` 下页面零向下链接至 `runtime/` 或 `dev/`，正文零出现具体仓库名、容器名或脚本语言名
- **写作硬格式红线**：零分号、零段尾与单元格尾句号、零非链接括号、零并列命名标题、零阶段过渡措辞

## Semantic

当理论经历集中扩张或准备进入下游实现阶段时，由独立只读 agent 先读 [VISION.md](../VISION.md)、[GLOSSARY.md](../GLOSSARY.md) 与[断言总览](assertions.md)，再对照以下七项维度执行对抗性语义巡检：

1. **愿景与标尺对齐**：逐项对照 [VISION 的 Compass](../VISION.md#compass)，辨认是否存在引入噪音、推断授权、叠加中间层或为迁移妥协污染公理的条目
2. **前提与原语可推性**：核对各领域核心规则能否从[前提](../theory/premise.md)与[原语](../theory/primitive/index.md)推出，识别未声明的隐含世界事实或原语冗余
3. **本体分层与抽象泄漏**：核对理论抽象、实践实例化与实现语义翻译的单向演进链，识别把具体工具、工作区特例或操作清单错放入理论层的内容
4. **跨领域概念碰撞**：重点严查核心概念对的 MECE 正交性，包括 `Record` 与 `Effect`、`Ownership` 与协议状态机、`Task` 生命周期与 `Closeout`、`Skill` 成立条件与派生清单、`Intent` 与 `Decision` 及 `Approval`
5. **跨页漂移与权威位置**：对照新旧页面检查术语漂移、双处复写与断言漏限定
6. **本体缺口**：识别下游设计反复依赖却尚未在理论层清晰建模的一等概念
7. **表达与文风纯度**：抽查正向定义、日常自然文风与词表收敛，防止抽象名词化堆砌

## Output

语义巡检输出按三个严重度分级呈现，每条附精确文件路径、行号与第一性剖析：

- **P0**：本体直接矛盾或硬层级错位，阻塞下游设计或实现
- **P1**：概念边界模糊、本体缺口或跨页口径冲突
- **P2**：局部重复、措辞规范偏差或文风打磨

面向 user 的决策点严格遵守[引领的 Questions](../theory/communication/leadership.md#questions)：打散排位，显式亮出相互冲突的底层指标与各自代价，不附隐含推荐
