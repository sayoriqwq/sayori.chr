# Lint

## Layers

依据 [VISION 的软硬分界](../VISION.md#tenets)与[前提](../theory/premise.md#agent)，本仓将质量守卫按用途拆分为两层：

| 层级 | 执行者 | 时机 | 守卫范围 |
| --- | --- | --- | --- |
| 确定性硬边界 | `.ok/scripts/{derive,links,lint}.mjs` | 每次修改与提交前 | 字段完整、自动路由、链接可达、不动点无环 DAG、理论零向下链接与纯标点硬格式 |
| 定期软语义巡检 | 独立只读审阅 agent | 理论大幅扩张、新增领域或阶段收口前 | 愿景对齐、前提可推、分层与抽象纯度、实体命名正交、中间态清理、跨领域闭合与文风词表 |

## Structural

`node .ok/scripts/lint.mjs` 仅守卫零语义歧义、违背必错的确定性硬边界：

- **依赖图硬边界**：`theory/premise.md`、`theory/language.md` 与 `theory/primitive/` 下页面零向上链接至上层领域、设计层或精选案例，`theory/` 下页面零向下链接至 `runtime/` 或 `dev/`
- **纯标点硬格式**：受管页面的正文与 frontmatter 零分号、零段尾项尾单元格尾句号、零非链接括号

凡须结合语境辨析真伪的语义约束均不以僵硬正则硬编码进脚本，统一归入下方语义巡检

## Semantic

当理论经历集中扩张或准备进入下游实现时，由独立只读 agent 先读 [VISION.md](../VISION.md)、[GLOSSARY.md](../GLOSSARY.md) 与[断言总览](assertions.md)，再对照以下七项维度执行对抗性语义巡检：

1. **愿景对齐**：逐项对照 [VISION 的 Compass](../VISION.md#compass)，辨认是否存在引入噪音、推断授权、叠加中间层或为局部便利污染公理的条目
2. **前提可推**：核对各领域核心规则能否从[前提](../theory/premise.md)与[原语](../theory/primitive/index.md)推出，识别未声明的隐含世界事实或原语冗余
3. **分层纯度**：核对理论抽象、实践实例化与实现语义翻译的单向演进链，识别理论层是否泄漏具体工具、代码框架、工作区特例或操作清单，以及正文是否混入建设进度与阶段中间态措辞
4. **概念正交**：严查核心概念对的 MECE 正交性如 `Record` 与 `Effect`、`Ownership` 与协议状态机、`Task` 生命周期与 `Closeout`、`Skill` 成立条件与派生清单、`Intent` 与 `Decision` 及 `Approval`，并辨别标题、表格首列与列表标签中是否把独立实体错误捏合为并列命名
5. **跨页一致**：对照新旧页面检查术语漂移、双处复写与断言漏限定
6. **本体缺口**：识别下游设计反复依赖却尚未在理论层清晰建模的一等概念
7. **文风纯度**：抽查正向定义、日常自然文风与词表收敛，防止抽象名词化堆砌

## Output

语义巡检输出按三个严重度分级呈现，每条附精确文件路径、行号与第一性剖析：

- **P0**：本体直接矛盾或硬层级错位，阻塞下游设计或实现
- **P1**：概念边界模糊、本体缺口或跨页口径冲突
- **P2**：局部重复、措辞规范偏差或文风打磨

面向 user 的决策点严格遵守[引领的 Questions](../theory/communication/leadership.md#questions)：打散排位，显式亮出相互冲突的底层指标与各自代价，不附隐含推荐
