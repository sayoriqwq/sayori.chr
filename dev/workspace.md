# Workspace

## Layout

工作区基座落实 [Workspace](../theory/agency/crew.md#workspace) 的逻辑隔离边界，为每个实例化工作区提供统一的轻量结构骨架：

| 组成 | 职责 | 维护边界 |
| --- | --- | --- |
| `AGENTS.md` | 工作区面向 agent 的薄入口，声明四个扩展槽并引用上游[愿景](../VISION.md)与[词表](../GLOSSARY.md) | 依据本区有效决定维护 |
| 单层平铺任务区 | 每个 Task 独占一层，入口为 `index.md`，按需存放 Spec 与 Ticket 载体 | 由所属 Mate 维护，状态由协作层承载 |
| 协作数据目录 | 本工作区专属的事件存储、本地易失状态与受管会话目录 | 由协作层管理，归入版本忽略边界 |
| 忽略规则基座 | 按文件职责分层的 `.gitignore` 模板，适用于采用版本记录仓的工作区 | 继承基座模板并按需追加本区嵌套独立仓 |
| `NOTES.md` | user 亲自组织的原始表达 | user 专写、agent 只读，见[特殊文件名](../theory/documentation/special-filenames.md) |

任务区保持单层平铺结构，使路径与链接在整个生命周期内保持稳定。一次性目标与常驻职责均由 Task 统一承载，遵循 [Task 的 Lifetime](../theory/delivery/task.md#lifetime)。术语与愿景直接通过指针引用上游真源，消费工作区不另建重复定义

## Wiring

工作区基座作为完整装配方案，在初始化配置中直接接入全机共享的协作层基础实现：

- **协作入口**：统一绑定共享的协作层宿主扩展包与协议命令行入口，消费工作区内保持零协作源码副本
- **环境端口**：通过工作区环境契约向协作层暴露本区工作树登记与环境观察范围，严格限定在本工作区作用域之内，见[跨区工作树扫描淹没本区发现](../cases/foreign-worktrees-noise.md)
- **工程基建**：统一装载基座发布的独立工程 Skill 包与确定性检查机制

## Slots

基于工作区基座实例化为具体消费工作区时，薄入口仅需填入以下四个扩展槽：

1. **仓库拓扑与形态**：声明本工作区采用版本记录宿主仓、独立单仓还是非版本化目录，标明公开性并列出旗下产品仓、测试仓与参考仓路径
2. **环境与服务合同**：提供构建与启动方式、本地或远程服务入口、浏览器会话约定与平台工具约束
3. **领域知识入口**：指向本区产品知识库、架构决定记录目录与外部信息检索路由
4. **薄适配与专有 Skill**：声明本区业务专有的薄适配 Skill 与特有规则，命名与共享层互异

## Visibility

工作区基座自身与实例化后的具体工作区遵循[变更的 Carrier](../theory/delivery/change.md#carrier)界定的公开性边界：

- **工作区基座自身**：作为公开分发的成品装配模板与工程包仓库，按正式交付产品仓标准执行语义化提交与严格内容甄别
- **私有工作区实例**：采用私有版本记录宿主仓的个人或内部业务工作区专注记录状态变迁与轻量溯源
- **公开工作区实例**：面向外部可见的公开宿主仓或公开单仓在每次提交前执行严格内容与敏感信息甄别
