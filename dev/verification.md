# Verification

## Layers

依据[验收的 Separate](../theory/delivery/acceptance.md#separate)，对工作区基座、Skill 包或业务代码的每次变更均按三层分别取证：

| 层次 | 核对对象 | 证明边界 |
| --- | --- | --- |
| 内容完成 | 源码、配置模板与自包含 Skill 正文 | 修改内容符合批准范围与格式契约 |
| 接入完成 | 宿主包装载器、命令行入口、工作区路由与部署实例 | 运行入口实际解析并加载到新版产物 |
| 使用验证 | 真实工作区任务与真实消费者运行路径 | 目标行为在真实环境与真实接口下成立 |

每层证据独立表述，缺少真实使用证据时如实写明待观察范围，并在后续真实任务中积累验证

## Seams

依据 [Spec 的 Seams](../theory/delivery/spec.md#seams)，工程测试体系围绕架构边界与协议不变量组织：

- **扩展点守卫**：在模块与端口边界验证外部行为承诺与协议不变量，保持内部实现可自由重构
- **真实消费**：单元测试替身与人工故障注入均单独标记其假设条件，涉及外部存储、挂载、网络与宿主集成的路径须经真实消费者复核
- **版本绑定**：每条证据绑定代码提交、运行配置、真实输入与观察结果，基线变更后仅复验受影响的切片

> 例：内存流替身接受带长度参数的读取而真实对象存储客户端仅支持无参读取，导致单元测试全绿后真实消费者调用失败，见[测试替身掩盖真实存储契约](../cases/storage-contract-mismatch.md)

## Purpose

不同交付目的的验证证据各自回答对应核心事实：

| 目的 | 证据回答的核心事实 |
| --- | --- |
| 缺陷修复 | 在原触发条件与真实路径下偏差消失，直接关联功能保持稳定 |
| 新功能 | 目标用户在约定入口可完成主流程，关键失败路径符合承诺 |
| 能力增强 | 指定不足得到缓解，受影响的既有能力保持正常 |
| 基础设施 | 在真实开发与运行场景下持续成立，条件动作按需发生且临时资源干净退出 |
| 维护重构 | 维护成本下降，真实消费者与既有外部契约保持兼容 |
| 安全加固 | 原越界路径被阻断，合法边界内行为保持畅通，并与历史数据影响核查分开记录 |

## Automation

工作区基座内置轻量确定性检查机制，专门守卫规则完全明确的机械检查项：

- **工作区卫生**：在当前工作区作用域内扫描已合入未清退的工作树、未纳入忽略的嵌套独立仓库以及进入暂存区的超阈值大文件
- **包契约校验**：校验基座发布的每份工程 Skill 包的自包含完整性、命名空间唯一性与内部引用可达性
- **入口一致性**：校验工作区薄入口的扩展槽结构与声明路径可达

自动化脚本按生命周期与审阅归属分流选型：

- **常驻与可复用脚本**：落入仓库长期维护、可能被复用或须经 user 审阅的脚本，统一采用所属体系的主技术栈编写，使审阅与维护保持技术栈一致
- **一次性临时脚本**：仅在当前会话命令行中服务单次探索、分析或验证的临时脚本，由 agent 按效率自由选用工具，随任务结束清除

涉及价值判断、工作范围取舍与接受缺口的决策保留给负责人。新增长期自动检查、钩子或流水线门槛须经有效批准
