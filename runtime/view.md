# View

本页落实[职责树的 Visibility](../theory/agency/crew.md#visibility)与 [Reentry](../theory/agency/crew.md#reentry)，定义 user 的控制面阅读视图与进出交互

## Surface

user 的控制面由终端对话与唯一的只读职责树视图构成：

- **统一入口**：容器层全局快捷键与普通终端查看命令打开同一份只读视图，保持单一入口与一致体验。仅保留能够可靠转发到同一视图的宿主入口
- **只读边界**：视图的职责限定为观察、筛选与导航。批准、决定与验收结论统一在对应 Station 的真实对话上下文中作出
- **零模型**：打开、切换、刷新、展开、进入与返回完全由确定性记录读取与有界现场观察完成
- **单域范围**：视图范围严格限定在当前工作区，每个工作区各自维护独立的视图与 Firstmate

## Tabs

顶部提供四个分类视角并附各自计数，每次聚焦一屏，按 user 认得的原诉求标识事项：

| 视角 | 内容 |
| --- | --- |
| 等你决定 | 目标为 user 的未决待决项，首行写明待决问题，展开见背景、选项与代价 |
| 需要留意 | 破坏有主或一致性的异常、有明确影响的 Outside、已收口 Task 的遗留 Effect 或责任 |
| 诉求结果 | 显式关联的已完成诉求摘要与影响说明，供回访查阅，成果核对仍归属[验收](../theory/delivery/acceptance.md) |
| 进行中 | 未收口的活跃 Task，每项一行，展示名称与最近有效结论 |

> 例：旧面板曾按十二小时短窗口过滤，user 离开数天返回后界面显示为空，只能从决策清单与长简报自行拼凑全貌，见[离开回归后的信息过载](../cases/reentry-overload.md)

## Reading

选中事项后，详情区按判断优先级分层呈现：

- **首层够用**：首层固定呈现当前结论、等待对象、下一步行动以及影响判断的阻断性例外，使用日常语言表达实际变化与影响
- **按需展开**：工作范围、Effect、关联 Station、原始汇报与证据路径按需展开。长文本正常换行，路径与原文可读到末尾
- **减法**：已有结局的失败、无遗留责任的缺报与已收口的 Task 退出主列表，界面仅渲染存在实际内容的章节与节点
- **诚实**：缺失、陈旧或不可读取的证据标明未知，读取失败显示计数未知，保持观察状态真实可辨

> 例：交付说明曾只堆叠内部结构术语与提交号而未说明实际变化，user 反馈看不懂具体做了什么，见[交付说明过于抽象](../cases/abstract-delivery.md)

## Interaction

- **键鼠完整**：同时支持纯键盘与纯鼠标完整阅读。鼠标悬停仅高亮当前行，单击才切换选中项。列表区与详情区独立滚动，展开与收起章节保持当前阅读位置稳定
- **真实调节**：外框面积与内部分隔调节仅暴露宿主真实支持的能力，布局偏好存于本机本地状态
- **状态栏**：具备原生状态栏的宿主在各 Station 常驻显示当前 Station 身份标签，待决与留意计数仅在非零或读取失败时显示

## Navigation

- **直接聚焦**：从视图进入运行中的 Station 时直接聚焦目标窗格，保持进程连续与原有布局稳定
- **同键返回**：通过同一全局快捷键或返回上个窗格回到视图原位置。原条目因已处理离开列表时，落点顺延至同一分类下一条或下一个非空分类
- **历史恢复**：进入已退出的历史 Station 通过显式恢复动作打开原会话，阅读与导航动作保持只读属性
