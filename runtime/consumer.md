# Consumer

## Distribution

协作层与工程层采用正式化的单一共享分发，全机维护唯一一套协作层入口与工程层入口：

- **协作层**：以标准宿主扩展包与统一协议命令行入口共享安装，提供协作机制、外部化内容说明与只读视图
- **工作区基座**：作为成品的工作区基础装配方案，接入协作层基础实现，提供静态基座配置、确定性检查机制与自包含的独立工程 Skill 包
- **发布**：对共享底座的改造在独立分支完成并通过边界验证，经 user 批准后合入主干并统一切换生效，工作区以显式发布批准代替本地源码副本与启动版本锁

## Contract

消费工作区保持轻薄，只提供本工作区独有的最小契约，并经工作区环境端口暴露给协作层：

| 项目 | 位置 | 内容 |
| --- | --- | --- |
| 运行目录 | 工作区专属数据目录 | 本工作区的事件存储、本地易失状态与受管会话目录 |
| 路由 | 工作区入口文档 | 遵守工程基座规范的薄入口，列出本区仓库、环境、知识入口与特有规则 |
| 专有 Skill | 工作区 Skill 目录 | 专用于本区业务的薄适配或专有 Skill，命名与共享层互异 |
| 工作材料 | 工作区自有组织 | Task 合同、设计依据、证据文档以及暴露给环境端口的工作树登记 |

协作协议与通用工程做法全机各保持唯一一份，工作区接入时确保本地仅留本区特有 Skill

## Domain

- **隔离**：每个工作区是独立领域，各自拥有完整的职责树、Firstmate、事件存储、本地状态与视图。不同业务领域彼此隔离节点、仓库与业务内容
- **回看**：单工作区默认零跨区配置。建设区需要跨区只读回看消费区 Case 以推动[进化回路](loop.md)时，通过显式只读来源登记声明目标路径，保持严格只读且仅提取脱敏协作规律

> 例：跨区登记文档曾将两个隔离工作区表述为同一棵职责树的上下级，导致本区不断衍生前置任务阻塞消费区验证，见[隔离工作区误作单一职责树](../cases/domains-as-one-tree.md)

> 例：环境检查曾按共享仓库全局枚举工作树，将另一工作区的二十六个工作树混入本区发现，见[跨区工作树扫描淹没本区发现](../cases/foreign-worktrees-noise.md)

## Border

一条规则的归属按作用域从广到窄依次匹配，首个满足条件的一层为其权威位置：

1. 跨具体实现恒成立的协作、交付、文档、Skill、Git 与进化原理，归入[理论](../theory/index.md)
2. 专用于协作引擎的派活、交回、记录、唤醒与视图设计，归入[协作层](index.md)
3. 成品工作区基础仓的目录骨架、基座配置、检查脚本与独立工程 Skill 装配规范，归入[工作区基座](../dev/index.md)
4. 仅对当前工作区实例、特定仓库或特定环境成立的事实、拓扑与业务适配，留在当前工作区

全部理论声明集中归入第一条，下游实现仓专注交付面向运行的代码、配置、脚本与独立包。共享底座保持工作区中立，特定工作区约定留在消费工作区

| 协作层 | 工作区基座 | 具体工作区 |
| --- | --- | --- |
| 派活、交回、验收、结束与退站 | 单层平铺任务骨架、扩展槽与协作层装配接线 | 仓库拓扑与性质声明、环境服务合同与领域知识 |
| 汇报、待决项、决定、批准、Effect 与 Case 记录 | 按职责分层的忽略基座与确定性卫生巡检机制 | 本区标签体系、发布脚本与平台专有适配 |
| 唤醒、来源信封、意图标注、焦点、`/branch` 与视图 | 独立自包含的工程 Skill 包与包边界校验 | 特定机器或业务环境的经验与薄适配 Skill |

> 例：委托交回后的核对与退站状态机属于协作层，见[确认方字段耦合死锁](../cases/confirmedby-deadlock.md)。已合入工作树的清退纪律与忽略文件规范换任意工作区均成立，属于工程层，见[工作区工程卫生规则缺位](../cases/git-hygiene-gap.md)
