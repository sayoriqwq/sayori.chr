# Wake

## Levels

[职责树的 Notify](../theory/agency/crew.md#notify)按注意力与额度代价分三级落实：

| 层级 | 形式 | 代价 |
| --- | --- | --- |
| 可查 | 追加进事件存储，由[视图](view.md)或按需读取取得 | 几乎没有 |
| 常驻 | 反映在宿主状态栏计数或界面提示，不开模型回合 | user 极少注意力 |
| 唤醒 | 触发目标节点的新模型回合 | 模型额度与上下文 |

变化默认落在可查一级。只有对方此刻不取得就会对状态、责任、依赖或下一步作出错误判断时，才提升为常驻或唤醒。正常进度只写记录，不打断 user，也不由 Firstmate 轮询转述

## Rules

| 来源 | 层级 | 条件 |
| --- | --- | --- |
| 目标为 user 的未决待决项 | 常驻 | 反映在状态栏计数与视图的等你决定分页 |
| 目标为上层作用域的待决项，包含交回、阻塞与协调 | 唤醒 | 目标节点空闲时每次观察最多开一个回合 |
| Firstmate 转入后台的任务结束 | 唤醒 | 送回退出状态与输出尾部，唤醒发起它的 Firstmate 会话 |
| 子节点声明交回但缺少最新汇报 | 唤醒 | 追问子节点一次，仍缺则记缺报 |
| 子节点做完工作后停下，既未交回也未留待决项 | 唤醒 | 到下一份汇报前最多追问一次，问其继续、交回或记待决项 |

- **增量观测**：通过事件存储的持久连接、增量游标与变更流驱动观察，避免周期性全量扫描历史事件
- **外部等待**：等待 CI、部署或外部系统时，通过受管阻塞命令把结局带回，不靠循环休眠轮询制造重复噪音

> 例：曾因汇报工具报错后节点仍声明结束，事件存储只有缺报而无交回通知，上层完全不知情，直到 user 追问才发现

## Delivery

严格区分三件不同的事：业务上是否未结、该版本通知是否已送达目标会话、原业务动作是否成功：

- **去重**：已送达目标会话的旧版本待决项在会话重载后保持业务可查，不再次唤醒模型。同一待决项更新版本或产生新交回时正常重新送达
- **失败**：底层投递报错或超时绝不标作已送达。重试设置明确上限，到达上限后停止盲目重试，向界面输出单行未知摘要并将分段耗时写入诊断日志，不向终端倾倒堆栈
- **核活**：向运行中节点发起唤醒前核对目标存活状态，已退出的会话无法唤醒，不对其空等

> 例：曾因已送达但业务未结的待决项缺少持久化送达状态，同一会话重载后再次被旧通知唤醒

## Limits

每个唤醒来源必须具备明确的停止条件：

- **阻塞转交**：对方无法自主解决时，例如缺权限、缺 user 判断或外部条件不可达，转为目标为 user 的待决项并停止自动唤醒
- **次数上限**：同一来源允许重复唤醒时设置硬上限，触顶后升级为异常留意或转交 user 决定
