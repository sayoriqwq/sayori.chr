# Wake

## Levels

[职责树的 Notify](../theory/agency/crew.md#notify)按注意力与额度代价分为三级：

| 层级 | 形式 | 代价 |
| --- | --- | --- |
| 可查 | 追加进事件存储，经[视图](view.md)或按需读取取得 | 几乎为零 |
| 常驻 | 反映在宿主状态栏计数或界面提示，保持模型静默 | user 极少注意力 |
| 唤醒 | 触发目标节点开启新的模型回合 | 模型额度与上下文 |

一般状态变化默认落在可查一级，正常进度仅写记录以便随时查阅。当某项变化若延迟取得就会导致对方对状态、责任、依赖或下一步作出错误判断时，再提升至常驻或唤醒一级

## Rules

| 来源 | 层级 | 触发条件 |
| --- | --- | --- |
| 目标为 user 的未决待决项 | 常驻 | 同步反映在状态栏计数与视图的等你决定视角 |
| 目标为上层作用域的待决项，包含交回、阻塞与协调 | 唤醒 | 目标节点空闲时每次观察最多开启一个回合 |
| Firstmate 转入后台的任务结束 | 唤醒 | 携带退出状态与输出尾部，唤醒发起它的 Firstmate 会话 |
| 子节点声明交回但缺少最新汇报 | 唤醒 | 追问子节点一次，仍缺失则记录缺报 |
| 子节点完成工作后停下，既未交回也未留待决项 | 唤醒 | 在下一份汇报产生前最多追问一次，引导其继续、交回或记待决项 |

- **增量观测**：经事件存储的持久连接、增量游标与变更流驱动观察，按新事件实时推进
- **外部等待**：等待 CI、部署或外部系统结果时，通过受管阻塞命令把结局作为后台任务结果带回

> 例：汇报工具报错后节点仍声明完成，事件存储仅记录缺报而缺少交回通知，导致上层沉默无知直到 user 追问，见[汇报失败后沉默交回](../cases/silent-report-failure.md)

## Delivery

送达机制将业务是否未结、该版本通知是否已送达目标会话、原业务动作是否成功三项事实分开记录与核对：

- **送达去重**：持久化记录每个版本待决项在目标会话的送达状态。会话重载后，已送达过的旧版本待决项继续在视图与存储中保持业务可查，仅当同一待决项更新版本或产生新交回时再次触发唤醒
- **失败边界**：底层投递报错或超时保持未送达状态，并按有界次数重试。达到上限后停止重试，向界面输出单行未知摘要并将分段耗时写入诊断日志
- **核活前提**：发起唤醒前先核对目标节点存活状态，仅向运行中的活跃会话投递唤醒

> 例：已送达但业务未结的待决项因仅存于内存集合，同一会话重载后被旧通知重复唤醒，见[焦点滞留与重载重复唤醒](../cases/focus-drift-reload-replay.md)

## Limits

每个唤醒来源均配置明确的停止条件：

- **阻塞转交**：当接收方因缺权限、缺 user 判断或外部条件不可达而无法自主推进时，转为目标为 user 的待决项并终止自动唤醒
- **次数上限**：允许重复唤醒的来源设置硬上限，触顶后升级为留意异常或转交 user 决定
