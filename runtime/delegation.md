# Delegation

本页落实[交接](../theory/agency/handoff.md)、[验收](../theory/delivery/acceptance.md)与[收口](../theory/delivery/closeout.md)在协作层的协议状态机

## Dispatch

上层经统一派活操作完成委派，按[交接的 Acceptance](../theory/agency/handoff.md#acceptance)采用机制确定性接收，并严格遵循后置提交点次序：

1. 校验派活前置、切片声明与隔离资源边界，按[交接的 Basis](../theory/agency/handoff.md#basis)准备交回产物、交回对象、结束条件、原轮批准入口与工作区基座入口。前置不满足时直接拒绝派发，不留半截资源
2. 在所属 Task 的容器工作区后台静默新开单窗格标签页并保持当前焦点稳定，将 Mate 排在 Sailor 之前，启动目标会话并完成工作声明注入
3. **提交点**：确认目标会话就绪且声明送达后，在持久存储原子写入目标工作的工作声明与负责变更，使下层执行作用域与上层视图持有完全对称的工作前置，随即在本地状态记录坐标并返回上层。启动或送达任一步失败均不写入负责变更，原负责人继续持有职责

> 例：派活曾仅在父作用域写入工作声明而交回未校验子作用域，导致子节点完成工作后验收入口以缺少子作用域声明为由拒收，见[交回缺少子作用域声明](../cases/return-missing-declaration.md)

## Facts

交回、验收与结束分属控制权回落、成果核对与生命周期终止三个维度，各自独立运作：

| 事实 | 写入方 | 记录 | 职责边界 |
| --- | --- | --- | --- |
| 交回 | 协作机制受节点触发写入 | 最新汇报与指向直接上层的交回待决项 | 机制落盘即构成控制权回落上层的接收点，节点保持存活以备追问并继续托管自身启动的活跃资源 |
| 验收 | 非作者核对者，由 user 判断 | 验收结论，含结果、核对者、原轮入口与 user 依据 | 表达成果接受或触发返工 |
| 结束 | 约定结束方，默认为派活上层 | 委托结束事件，写入决定方的可信作用域 | 唯一决定节点能否进入退站 |

- **作用域即身份**：委托结束的身份唯一取自事件写入时的可信作用域，使只有约定结束方能够闭合退站门禁
- **机制写事实**：交回汇报与待决项由协作机制原子落盘，不依赖模型仅在会话文本中口头汇报。上层在完整处理完交回待决项后再推进消费确认游标，处理中途中断时持久队列保持可幂等恢复
- **交回前置守卫**：节点发起交回前须具备本次工作最新的汇报与完整的本作用域工作声明。任一前置缺失或汇报写入失败时，机制在阻塞通道打开指向直接上层的待决项写明缺项，待补齐解除阻塞后再发出正常交回
- **验收可追加更正**：验收按单次交回结算。同一交回支持追加新的验收结论并以最新一条为准更正先前判断，新的交回支持再次结算。退回时打开返工待决项并重新移交执行控制权，user 的判断始终有效

> 例：旧协议曾把合同里的自由文本确认方字符串直接当作退站门禁，合同写 Firstmate、验收入口写 user 且禁止二次验收，导致两条已完成委托永久死锁，见[确认方字段耦合死锁](../cases/confirmedby-deadlock.md)

## Condition

委派时约定的结束条件由两种抽象形态构成，使协议层独立于具体业务事件：

- **随任务撤除**：默认值，以所属 Task 的任务撤除事件作为结束依据，适用于仍可能被追问的 Sailor 与分出的讨论节点
- **按指定事件结束**：以一个发生在首次派活之后、属于同一子树的客观事件标识作为结束依据，例如阶段收口、验收结论或上层主动写下的委托结束事件

## Closeout

协作层落实[收口的 Levels](../theory/delivery/closeout.md#levels)，将阶段交付与任务终结拆为两个独立事件：

- **阶段收口**：Spec 交付或阶段切片完成时由负责人写入阶段收口事件，载明本阶段交付摘要、记录持久化状态与阶段级 Byproduct 结局。所属 Task 留在进行中视角并保持活跃延续，常驻 Task 的阶段合并统一走此路径
- **任务撤除**：一次性 Task 达成终点、工作取消或 user 明确下达常驻 Task 清退时由负责人写入任务撤除事件，载明撤除原因、剩余责任去向与 Task 级 Effect 结局回执，覆盖所有终结路径
- **责任留存**：任务撤除后该域退出进行中视角，尚未收回的 Byproduct 或未转交的遗留责任留在留意视角等待结局

## Retire

节点满足结束条件后发起退站，按以下步骤核验与释放：

1. 核验结束条件成立：随任务撤除时核对所属 Task 已写入任务撤除事件，按指定事件结束时核对目标事件真实存在且晚于首次派活
2. 核验本作用域责任清零：确认无未送达的交回记录，当前作用域下所有待决项已解决，且全部受管活跃资源与 Effect 已有结局。任一项未清零时退站门禁直接拒绝
3. 结束会话、清理本地运行占用并关闭受管独占空标签页。当 user 焦点恰好停留在已收口的独占空标签页上时，关闭该标签页并将焦点切回本工作区的 Firstmate。共享或复用的标签页保持开启
4. 节点异常中止或终端外部关闭后，执行显式对账流程，先只读核对容器快照与原始终端身份，经确认后再应用补记释放

> 例：受管节点退站时因独占空标签页恰好持有焦点而中止清理且未跟进，导致已收口窗口长期滞留，见[聚焦独占空标签页滞留](../cases/focused-retired-tab.md)
