# Delegation

本页落实[交接](../theory/agency/handoff.md)、[验收](../theory/delivery/acceptance.md)与[收口](../theory/delivery/closeout.md)在协作层的协议状态机

## Dispatch

上层经统一派活操作完成委派，派发成功标志工作已送达。派活按以下次序执行：

1. 原子写入目标工作的工作声明与负责变更，使下层执行作用域与上层视图持有完全对称的工作前置
2. 按[交接的 Basis](../theory/agency/handoff.md#basis)交代交回产物、交回对象与结束条件，附上有效批准的原轮入口与所需工程规范入口
3. 在所属 Task 的 Herdr workspace 后台静默新开单窗格标签页并保持当前焦点稳定，将 Mate 排在 Sailor 之前，启动目标会话并在本地状态记录坐标，随即返回上层

派活仅在切片明确后按需创建对应工作资源，保持职责边界与资源边界一致

> 例：派活曾仅在父作用域写入工作声明而交回未校验子作用域，导致子节点完成工作后验收入口以缺少子作用域声明为由拒收，见[交回缺少子作用域声明](../cases/return-missing-declaration.md)

## Facts

交回、验收与结束分属控制权移交、成果核对与生命周期终止三个维度，各自独立运作：

| 事实 | 写入方 | 记录 | 职责边界 |
| --- | --- | --- | --- |
| 交回 | 被派发节点 | 最新汇报与指向直接上层的交回待决项 | 触发上层核对，保持节点存活以备追问 |
| 验收 | 非作者核对者，由 user 判断 | 验收结论，含结果、核对者、原轮入口与 user 依据 | 表达成果接受或触发返工 |
| 结束 | 约定结束方，默认为派活上层 | 委托结束事件，写入决定方的可信作用域 | 唯一决定节点能否进入退站 |

- **作用域即身份**：委托结束的身份唯一取自事件写入时的可信作用域，使只有约定结束方能够闭合退站门禁
- **交回前置守卫**：节点发起交回前须具备本次工作最新的汇报与完整的本作用域工作声明。任一前置缺失或汇报写入失败时，机制在阻塞通道打开指向直接上层的待决项写明缺项，待补齐解除阻塞后再发出正常交回
- **验收可追加更正**：验收按单次交回结算。同一交回支持追加新的验收结论并以最新一条为准更正先前判断，新的交回支持再次结算。退回时打开返工待决项，user 的判断始终有效

> 例：旧协议曾把合同里的自由文本确认方字符串直接当作退站门禁，合同写 Firstmate、验收入口写 user 且禁止二次验收，导致两条已完成委托永久死锁，见[确认方字段耦合死锁](../cases/confirmedby-deadlock.md)

## Condition

委派时约定的结束条件由两种抽象形态构成，使协议层独立于具体业务事件：

- **随任务收口**：默认值，以所属 Task 的收口事件作为结束依据，适用于仍可能被追问的 Sailor 与分出的讨论节点
- **按指定事件结束**：以一个发生在首次派活之后、属于同一子树的客观事件标识作为结束依据，例如一次验收结论或上层主动写下的委托结束事件

## Closeout

- **一等收口**：一个 Task 结束时由负责人写入任务收口事件，载明收口原因、剩余责任去向与 Effect 结局回执
- **全路径覆盖**：正常交付、直接中止或退出关注的工作统一经任务收口事件完成收口并离开进行中视角，无论该工作此前是否产生过交回记录
- **责任留存**：任务收口后该域退出进行中列表，尚未收回的 Byproduct 或未转交的遗留责任留在留意视角等待结局

## Retire

节点满足结束条件后发起退站，按以下步骤核验与释放：

1. 核验结束条件成立：随任务收口时核对所属 Task 已写入任务收口事件，按指定事件结束时核对目标事件真实存在且晚于首次派活
2. 核验本作用域责任清零：确认当前作用域下所有待决项已解决且全部 Effect 已有结局
3. 结束会话、清理本地运行占用并关闭受管独占空标签页。当 user 焦点恰好停留在已收口的独占空标签页上时，关闭该标签页并将焦点切回本工作区的 Firstmate。共享或复用的标签页保持开启
4. 节点异常中止或终端外部关闭后，执行显式对账流程，先只读核对容器快照与原始终端身份，经确认后再应用补记释放

> 例：受管节点退站时因独占空标签页恰好持有焦点而中止清理且未跟进，导致已收口窗口长期滞留，见[聚焦独占空标签页滞留](../cases/focused-retired-tab.md)
