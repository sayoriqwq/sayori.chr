# Delegation

本页落实[交接](../theory/agency/handoff.md)、[验收](../theory/delivery/acceptance.md)与[收口](../theory/delivery/closeout.md)在协作层的协议状态机

## Dispatch

上层经统一派活操作一次完成委派，派发成功只说明工作已送达：

1. **对称声明**：原子写入目标工作的工作声明与负责变更，使下层执行作用域与上层视图共享同一工作前置，避免派活成功却在交回或验收时因缺少声明被拒收
2. **明确依据**：按[交接的 Basis](../theory/agency/handoff.md#basis)交代交回什么、交回给谁、结束条件是什么，附上有效批准的原轮入口与所需工程规范入口
3. **单窗启动**：在所属 Task 的 Herdr workspace 新开不抢焦点的单窗格标签页，Mate 在前，Sailor 在后，启动目标会话并在本地状态记录坐标，随后立即返回

派活不把多个执行者分屏到同一标签页，也不在切片确定前预建超出范围的外部资源

> 例：曾因派活只在父作用域写工作声明而交回不校验子作用域，导致节点完成工作后验收入口以缺少子作用域声明为由拒收，交回无法结算

## Facts

交回、验收与结束彼此独立，各守一条边界：

| 事实 | 写入方 | 记录 | 作用 |
| --- | --- | --- | --- |
| 交回 | 被派发节点 | 最新汇报与指向直接上层的交回待决项 | 唤醒上层核对，不结束 Station |
| 验收 | 非作者核对者，由 user 判断 | 验收结论，含结果、核对者、原轮入口与 user 依据 | 表达接受或触发返工，不门控退站 |
| 结束 | 约定结束方，默认为派活上层 | 委托结束事件，写入决定方的可信作用域 | 退站的唯一门禁 |

- **身份即作用域**：结束委托的身份由事件写入时的可信作用域决定，不把调用参数里的自由文本字符串当作身份凭据，下层无法替上层自证结束
- **交回阻断**：交回前必须存在本次工作最新的汇报且本作用域工作声明完整。写入失败或前置缺失时，机制拒绝生成成功交回，改为在阻塞通道打开指向直接上层的待决项写明缺项，补齐后解除阻塞再正常交回
- **验收可更正**：验收按单次交回结算。同一交回可以追加新的验收结论，以最新一条为准更正错判，新的交回可以再次结算。退回时打开返工待决项，user 的判断恒有效

> 例：曾把合同里的确认方字符串当作退站门禁，合同写 Firstmate、实际验收写 user 且禁止同工作二次验收，导致两条已完成的委托永久死锁无法退站

## Condition

委派时约定的结束条件只有两种，协议不在事件结构中枚举具体业务事件：

- **随任务收口**：默认值，随所属 Task 收口而结束，适用于仍可能被追问的 Sailor 与分出的讨论节点
- **按指定事件结束**：以一个发生在首次派活之后、属于同一子树的客观事件标识为止，例如一次验收结论或上层主动写下的委托结束事件

## Closeout

- **一等收口**：一个 Task 结束时由负责人写入任务收口事件，记录收口原因、剩余责任去向与 Effect 结局回执
- **覆盖无交回**：正常交付、直接中止或不再关注的工作均通过同一收口事件离开进行中列表，不要求必须存在交回记录才能收口
- **减法不丢责**：收口后该 Task 退出进行中视图，尚未收回的 Byproduct 或未转交的遗留责任仍留在留意视图

## Retire

节点满足结束条件后发起退站，按确定性次序核验与释放：

1. **条件核验**：随任务收口时核对所属 Task 已收口，按指定事件结束时核对目标事件真实存在且晚于首次派活
2. **责任清零**：核对本作用域无未决待决项，且无尚未结局的 Effect
3. **释放**：结束会话、清理本地运行占用并关闭受管独占空标签页。即便 user 当前焦点停留在已收口的独占空标签页上，同样关闭该标签页并将焦点切回本工作区的 Firstmate。复用或非独占的标签页绝不关闭
4. **对账**：节点异常中止或终端外部关闭后，通过显式只读核对与确认应用，对照容器快照与原始终端身份补记释放，不依赖脱离会话的后台脚本，也不对未知状态盲猜清理

> 例：曾因受管节点退站时独占空标签页恰好有焦点而放弃关闭且不再跟进，导致已收口的窗口长期残留
