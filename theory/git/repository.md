# Repository

## Kinds

协作环境中的 Git 仓库按承载职责分为两类，二者各自遵循独立的提交与卫生标准：

| 类别 | 承载职责 | 历史形态 | 面向读者 |
| --- | --- | --- | --- |
| 产品仓 | 承载对外交付成果的正式演进，例如源码、理论文档或可分发工具包 | 按语义化提交规范组织的变更历史 | 协作者、评审者与使用者 |
| 宿主仓 | 承载工作现场的状态变迁与过程溯源，充当外层事件源 | 按工作域与节点演进的状态记录流 | 负责该域的维护者与 user |

## Visibility

仓库性质与公开性共同决定哪些内容可以安全提交进版本历史：

- **产品仓与公开宿主仓**：面向外部可见或公开分发，每次提交均严格甄别内容边界，过滤凭据、私有环境信息与局部调试噪声
- **私有宿主仓**：自创建起即限定在私有作用域内，以完整记录状态变迁与事后溯源为第一目标，允许激进节奏提交以忠实保留真实工作现场

## Tracking

版本跟踪与忽略边界沿文件职责划分，使任意工作域与子仓均按同一原则自动归类：

- **持久工作记录**：合同、规格、决定、回执、索引与正式文档按职责纳入跟踪
- **运行易失与私密实体**：运行期数据、本地缓存、凭据与本机私有配置归入忽略规则
- **独立版本域**：嵌套于工作现场内的其他独立版本库各自维护历史，在外层宿主仓归入忽略规则
- **证据体量**：截图、录像与高体量日志等大体积原始证据留在受控外部位置或本机，版本库仅保留轻量索引、摘要与结论

> 例：工作区缺少按职责划分的忽略规则与工程卫生规范时，交接文档被白名单挡住，而嵌套独立仓库与大体积测试证据长期污染仓库状态，见[工作区工程卫生规则缺位](../../cases/git-hygiene-gap.md)

## Weight

外层宿主仓定位为轻量方便的溯源入口与记录源，只维护支撑状态回溯的最小结构。无远端的纯本地宿主仓按轻量记录源对待，接受其本地易失属性，专注日常溯源效率
