# Commit

## Integration

代码与测试开发按阶段区分局部试错与正式交付：

- **Attempt**：在独立工作树内围绕同一需求反复尝试、验证与修正产生的过程提交，服务于局部探索与迭代
- **Run**：成果准备提审或正式合入产品主干的交付阶段。接入主干前先基于目标基线变基，再按文件级粗粒度将反复试错重整为语义清晰的提交，遵循经典语义化提交规范。粒度以按文件组表达清晰变更单元为准，使主干历史整洁可读
- **追加修复**：提审或合入之后针对评审意见与新发现问题的修正，以独立明确的语义提交记录，与先前的本地试错保持清晰界限

## Ownership

宿主仓作为外层溯源事件源，沿[职责树](../agency/crew.md)分配提交权责：

- **Mate 分权**：每个 Mate 负责维护并提交所属 Task 目录内的合同、记录与回执，职责直接清晰
- **Firstmate 协调与兜底**：Firstmate 负责公共根级入口与跨任务协调。分工清晰时各 Mate 的写入范围互不重叠，一旦出现索引或文件冲突，交由 Firstmate 统一整合写入
- **收口信号**：某 Task 目录持续存在未提交记录时，Firstmate 可直接据此排查该 Mate 尚未完成收口

## Concurrency

同一仓库存在他人在途未提交改动时，执行节点只精确暂存自身职责范围内的路径并核对暂存差异后提交，完整保留他人的未提交工作现场

## Review

工作树的未提交差异是 user 检查当前工作状态与逐行审阅细节的直接现场：

1. 当 user 明确提出审阅差异时，保留未提交工作树现场直至 user 审阅通过或明确阶段结束
2. 审阅通过或阶段结束后立即执行提交，将版本留档作为[收口](../delivery/closeout.md)必须落实的必要 Effect 完成落盘

文件写入、Git 提交、责任接收、业务验收与远端推送分属独立事实，各自按环境状态核实，推送与远端操作按 [Approval](../agency/approval.md) 核对
