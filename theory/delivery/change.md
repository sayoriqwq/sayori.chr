# Change

## Carrier

协作中承载变更的版本化载体按用途与公开性界定两项正交边界：

| 类别 | 承载职责 | 历史形态 | 面向读者 |
| --- | --- | --- | --- |
| 正式交付载体 | 承载对外交付成果的演进，例如源码、理论或可分发包 | 按语义规范组织的清晰变更历史 | 协作者、评审者与使用者 |
| 过程记录载体 | 承载工作现场的状态变迁与过程溯源，持久化工作文档与状态快照 | 按任务与阶段演进的留档记录流 | 负责该域的维护者与 user |

安全边界由载体的公开性决定：

- **公开载体**：面向外部可见或公开分发的载体，每次提交前严格甄别内容边界，过滤凭据、私密环境信息与局部调试噪声
- **私有记录载体**：自始限定于私有作用域，以忠实留痕与事后溯源为先，允许激进节奏的留档提交，按轻量溯源定位维护而无须建为重型备份平台

跟踪与忽略边界沿文件职责划分：持久工作记录纳入跟踪，运行易失数据、凭据、本机私有配置与嵌套独立版本域归入忽略，大体积原始证据留在受控外部位置、版本载体仅保留索引与摘要

## Integration

成果演进按阶段区分探索试错与正式交付：

- **Attempt**：在隔离副本内围绕同一需求反复尝试、验证与修正产生的过程变更，服务于局部探索与迭代
- **Run**：成果准备提审或正式合入主干的交付阶段。接入主干前先对齐目标基线，再按粗粒度语义单元将反复试错重整为清晰历史，使主干表达逻辑演进
- **追加修复**：提审或合入之后针对评审意见与新发现问题的修正，以独立明确的语义记录呈现

## Isolation

独立开发任务在隔离副本中推进，与主干现场分离，并在工作区环境契约中登记用途、负责人与退出条件

共享载体上并发存在他人在途未提交改动时，执行者只精确操作自身职责范围内的文件，完整保留他人的未提交现场

隔离副本的清理节奏联动 [Task 的 Lifetime](task.md#lifetime)：阶段性开发副本在成果合入主干且确认无活跃消费方后立即清退，常驻 Task 持有的长期副本保留至 user 明确下达撤除

## Review

未落盘的当前差异是 user 检查工作状态与逐行审阅细节的直接现场：

1. 当 user 明确提出审阅差异时，保留未提交现场直至审阅通过或明确阶段结束
2. 审阅通过或阶段结束后立即完成版本持久化，使[记录](../primitive/record.md)完整落盘

过程记录载体按[职责树](../agency/crew.md)实行 Mate 级分权持久化：每个 Mate 维护并提交所属 Task 的记录，Firstmate 负责公共根级入口与跨任务协调。并行分工避免范围重叠，出现冲突时交由 Firstmate 统一整合写入。某 Task 持续存在未提交记录时，构成 Firstmate 排查该节点尚未完成收口的直接信号

过程记录载体的本地提交归属 [Record](../primitive/record.md) 持久化，独立于 [Effect](../agency/effect.md) 登记。正式交付载体的隔离副本与临时分支属于 Byproduct，对外推送、发布与提审跨越共享与公开边界，按 Intended Effect 与 [Approval](../agency/approval.md) 核对
