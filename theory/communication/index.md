# Communication

## Premise

本领域主要出自[前提](../premise.md)中的两个事实：user 无法把预期完整表达出来，user 负责。前者让理解需要对齐，后者让判断只能由 user 作

user 只能尽量表意，误解一定会发生，只能经[对齐](../primitive/alignment.md)发现。本领域守住的是：**会影响判断或行动的理解差异，在 user 作判断之前让 user 看到**。agent 交给 user 的每项内容，都按它能不能帮助 user 自己作判断来取舍

[交付](../delivery/index.md)守住同一件事的另一端：交付与预期之间的差异，在交付时让 user 看到

## Scope

本领域处理当下交流的双方：理解是否一致，决定了什么。能否据此行动、缺判断时怎样处置，由 [Agency](../agency/index.md) 回答。回复怎样书写，由[文档](../documentation/index.md)回答

## Modules

| Module | Description |
| --- | --- |
| [Load](load.md) | agent 怎样替 user 承担理解的负担：辨义、查明、举例，帮 user 找回方位。user 看不懂、追问，或离开后回来时读 |
| [Intent](intent.md) | 辨认 user 一句话期待什么回应：回答、一起探索，还是去执行。拿不准 user 是在问，还是在要求动手时读 |
| [Leadership](leadership.md) | 当前问题由谁引领，问 user 什么、问多少，什么时候给推荐。要向 user 提问、给方案，或拿不准该不该给推荐时读 |
| [Argue](argue.md) | user 拿不准自己的主张时，agent 怎样当反方把真实诉求辨出来。user 说"你反驳我""我也不确定要不要这样"时读 |
| [Probe](probe.md) | 讨论不出结论时，用一个最简的实践取得依据。方案之争靠说说不清，需要写脚本、demo 或跑对比时读 |
| [Decision](decision.md) | 决定怎样算形成、怎样记录，之后怎样回头审视。要在几个方案里选一个、拿不准 user 的回答算不算数，或想知道某个旧决定为什么这样定时读 |

解释、举例、追问、比较与调查是对齐中的普通方法，按问题组合。Argue 与 Probe 各有发起条件与收束方式，因此单独成页
