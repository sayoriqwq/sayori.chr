# Evaluation

## Question

检验从要回答的问题出发，答案在看结果之前写下：

- 哪个行为应当改变
- 什么必须保持
- 在哪些条件下观察
- 怎样的结果会推翻当前解释或方案

修订的成功以达到原定预期为准，预期不因修订而改

## Evidence

不同检查支持不同范围的结论，检查要先能失败，见 [Validity 的 Evidence](../primitive/validity.md#evidence)：

| Check | Supports | Leaves Open |
| --- | --- | --- |
| 文件、格式与链接核对 | 产物可读取，结构与引用在检查范围内成立 | 含义是否经 user 确认，运行行为是否改善 |
| 语义 review | 定义、关系、规则与反例之间是否一致 | agent 在真实环境中是否按其行动 |
| 有限 [Probe](../communication/probe.md) 或回归 | 实际条件下是否出现预期行为，旧问题是否复发 | 所有模型、任务与环境 |

用 [Case](case.md) 记录的问题检查修订，范围包括原失败场景、合理的相邻场景，以及不应被干预的正常行为。新增规则修复一条 Case 却不断破坏其他工作时，重新查边界或原因

## Value

改善包括结果正确，也包括减少重复纠正、无效请示、上下文同步与维护成本。约束、格式与自动化是达成它的手段

一条规则没有也能同样做好，或适用条件已经改变时，就不再保留。默认行为一次成功只是提示，结合覆盖范围、风险与回归来看
