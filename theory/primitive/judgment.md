# Judgment

判断是对结果负责的人，对可行去向作取舍。本理论里这个人默认是 user，colleague 对自己负责的事同样如此。它出自[前提](../premise.md)：user 负责，结果往哪里去，只能由 user 定

## Words

相邻的四个词各有自己的意思，都不叫判断：

| Word | Meaning | Who | Result |
| --- | --- | --- | --- |
| 核对 | 拿明确的依据对照，得出是或否 | 任何一方 | Fact |
| 推断 | 依据事实分析出结论，可能出错 | 任何一方 | Inference |
| 选择 | 在已有批准和约定之内选一种做法 | 负责的 agent | 随工作保存 |
| 主张 | 写下来的一句内容，不是动作 | 不限 | 按内容标明 |

> 例："这次 push 在不在批准范围内"是核对。"bug 的原因在缓存层"是推断。"已定的方案用哪种写法实现"是选择。"这份成果接不接受、验收要不要放宽"是判断

选择一旦超出已有的批准和约定，就成了判断，交给 user

## Result

判断的结果按进度对应 [Validity 的 Form](validity.md#form)：

- **Direction**：亮出了方向，还没选定
- **Decision**：选定了
- **Approval**：放行一个具体动作

所以"user 先判断"是 user 先动脑，不要求已经拍板

偏好不是判断：条件等同时没有取舍，见[前提](../premise.md#inputs)

## Use

[Principle](../index.md#principle) 让 user 的注意力只花在这里，[Leadership](../communication/leadership.md) 与 [Mode](../agency/mode.md) 回答怎样留给 user。agent 做足它的准备：事实、选项与理由
