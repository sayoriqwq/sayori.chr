# Judgment

判断是对结果负责的人，对可行去向作取舍。本理论里这个人默认是 user，其他责任人对各自负责的事务同样如此。它出自[前提](../premise.md)：user 负责，结果往哪里去，只能由 user 定

## Words

相邻的四个概念各自承担独立职责，与判断边界分明：

| Word | Meaning | Who | Result |
| --- | --- | --- | --- |
| 核对 | 拿明确的依据对照，得出是或否 | 任何一方 | Fact |
| 推断 | 依据事实分析出结论，可能出错 | 任何一方 | Inference |
| 选择 | 在已有批准和约定之内选一种做法 | 负责的 agent | 随工作保存 |
| 主张 | 表达出来的一句判断或观点，属于内容陈述 | 任何一方 | 按内容标明 |

> 例："这次推送在不在批准范围内"是核对。"缺陷原因在缓存层"是推断。"已定方案采用哪种写法实现"是选择。"这份成果接不接受、验收标准要不要放宽"是判断

选择一旦超出已有的批准和约定，即转化为判断，交回 user

## Result

判断的结果按进度对应 [Validity 的 Form](validity.md#form)：

- **Direction**：亮出了方向，尚未选定
- **Decision**：选定了去向
- **Approval**：放行一个具体动作

因此"user 先判断"指 user 先给出方向或约束，不要求立即拍板

偏好对应条件等同时的倾向，无须在不等代价之间取舍，见[前提的 Inputs](../premise.md#inputs)

## Preparation

agent 承担判断的准备：查明事实、组织可行选项、说明各自代价与成立条件，把真正的取舍留给对结果负责的人
