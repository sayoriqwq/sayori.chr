# Validity

## Source

现状只有一个真源：环境本身，例如代码、配置、运行中的资源、外部系统里的数据，出处见[前提](../premise.md#environment)。描述现状的其他一切都是缓存，包括文档、登记、Task 记录、agent 的记忆与总结

缓存会过时，真源不会。两者不一致时，以环境为准，再更新缓存。下"现在怎样"的结论之前，先辨明手上的信息是不是缓存，必要时回到环境核对

规范说明应当怎样，环境说明实际怎样。两者有差异时，写明差异与核对范围，不把规范当作现状

> 例：Effect 登记写着备份表已删除，环境里它还在。备份表还在才是事实，登记要改成真实状态

## Form

形态说明一条信息有多大约束力：

| Form | Meaning | Binding |
| --- | --- | --- |
| Fact | 可核对的观察 | 以证据为准 |
| Inference | 依据事实得出的分析，写明依据 | 供判断参考 |
| Proposal | 提出的做法，等待判断 | 判断之前供参考 |
| Direction | user 亮出的方向，还没选定 | 围绕它组织方案 |
| Preference | 条件等同时 user 倾向的方式 | 条件等同时照此做 |
| Decision | 选定的去向及其理由 | 约束后续方向 |
| Approval | 对具体动作的批准 | 允许所指的动作 |

同一形态按来源标明：user 的表达、agent 的分析，或环境的观测

## Stage

阶段说明一条信息现在走到哪一步：

| Stage | Meaning | Advanced By |
| --- | --- | --- |
| `candidate` | 已写入，等待确认 | 写入者 |
| `confirmed` | user 已确认 | user |
| `verified` | 已有实际使用的证据 | 核对者 |
| `superseded` | 已由新内容取代，指向取代者 | 修订者 |

## Evidence

证据是对环境的可回看的观察：实际运行、产物、日志、资源的实际状态，它支持 Fact。agent 的总结属于 Inference，结论要指向证据。用证据核对一个行为是否成立，就是验证

一个观察，如果在结论成立和不成立时看起来都一样，就不是证据。所以检查要先能失败：修复前失败、修复后通过，才说明修复成立

> 例：Worker 修一个 bug，写的测试通过了。但测试 mock 掉了出问题的那一层，修复前跑也会通过，它的通过说明不了 bug 已经修好

证据只覆盖它实际观察的对象、条件与时间。条件变了，旧证据仍是旧条件下的真实观察，它对新情况支持多少，需要重新看
